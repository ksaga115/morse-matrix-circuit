# morse-matrix-circuit

ボタンのタップ長でモールス信号を入力し、アルファベットにデコードするシングルページの Web アプリです。
入力中は、モールス符号の遷移ツリー（回路図風のチャート）上で現在のたどっている経路が光ります。

## 使い方

1. 画面右下の **SIGNAL** ボタンを押します（PC ではスペースキーでも打てます。押している間が「押している」扱い）。
   - 短く押す → **・（トン）**
   - 長く押す → **ー（ツー）**
2. 押すたびに上部の **Incoming Code** に現在の符号が表示され、チャート上の対応するノードと配線が点灯します。
   - 青い線 = ・、赤い線 = ー
3. 一定時間ボタンを押さないと、その符号が 1 文字として確定し、**Decoded Message** に追加されます。
4. **SYSTEM RESET** を押すと、入力中の符号とデコード済みメッセージをすべて消去します。

### 速さ（SPEED）

標準のモールスの決まりどおり、**1 単位 = 1200 ÷ WPM（ms）**で、・ = 1、ー = 3、符号の間 = 1、文字の間 = 3、単語の間 = 7 単位です。
初期値は **8WPM（1 単位 150ms）**、5〜30WPM で変えられます。超音波で送るときは、部屋の反響で ・ と ・ の間が埋まりやすいので、速くしすぎないのがこつです（PC → スマホで 15WPM は届かず、8WPM で届いた実績があります）。スライダーの下に、今の速さでの各長さ（ms）が出ます。

受け取る側は、それぞれの真ん中で判定します。

| 判定 | 境目 |
| --- | --- |
| ・ / ー | 2 単位（長短 AUTO がオンなら、受け取った長さから自動で決めた値） |
| 1 文字の確定 | 2 単位の間 |
| 単語の区切り（空白） | 5 単位の間 |

手で打つとき、文字の間を長く空けすぎると単語の区切りと見なされて空白が入ります。そう感じたら SPEED を下げてください（例: 8WPM なら 1 単位 150ms）。

## 無線モード（超音波で 2 台のスマホをつなぐ）

ネットも Wi-Fi も Bluetooth も使わず、**人にほぼ聞こえない高い音（初期 18.5kHz）**でモールスを送り合います。

1. 2 台とも上の Pages の URL で開き、**欧文 / 和文**と **FREQ** を同じ値にそろえる（SPEED も近い値に）
2. 送る側は **TX 送信**（音量を最大に）、受け取る側は **RX 受信**（マイクの許可を求められたら許可）
3. 送る側で SIGNAL を押すか、文章を入れて **SEND** を押す
4. 受け取る側の回路図が光り、Decoded Message に文字が出ます

- **SEND（自動送信）**: 打った文章を、SPEED の標準の長さ（1 / 3 / 1 / 3 / 7 単位）で自動的に打ちます。送信中はもう一度押すと止まります。LOCAL のままでも音を出さずに回路図だけ動かせます
- **長短 AUTO**（初期オン）: ・ と ー の境目を、直近に受け取った長さから自動で決めます。直近 16 打を「短い組」と「長い組」に分け、その真ん中（対数で）を境目にします。打つ人の癖や、部屋の反響で音の尻尾が伸びる分にも合わせられます。2 組がはっきり分かれる（1.8 倍以上、どちらも 2 打以上）までは 2 単位を境目にするので、最初の 1〜2 文字はその値で読みます。0.4 単位未満の打ちは雑音とみなして学びません。相手が SPEED より遅いとわかったときは、文字の確定や単語の区切りの間もその遅さに合わせます
- **測った長さの表示**: Incoming Code の下に、受け取った ・ / ー の長さ（ms）と今の境目が出ます。長短がうまく分かれないときの手がかりにしてください
- **RX-TH / LEVEL**: 受信側のメーターが赤い線を超えると「鳴っている」と判定します。拾えないときは RX-TH を下げ、誤反応するときは上げてください
- **速くしたいとき**: 2 台とも SPEED を上げます（20WPM で 1 単位 60ms）
- **FREQ** は 15〜23kHz。18kHz 前後でも聞こえる人がいるので、聞こえるなら上げてください。上げるほど聞こえにくくなる代わりに、機種によっては届きにくくなります
- 作れる音の上限は、その端末のサンプリング周波数の半分です（48kHz なら 24kHz、44.1kHz なら 22.05kHz）。超えると低い音に化けて聞こえてしまうので、TX / RX を始めたときに 1kHz の余裕を残した値までに FREQ の上限を自動で下げます（ステータス欄に「この端末は ○kHz まで」と出ます）。2 台で上限が違うときは、低いほうに合わせてください
- 音の出だしと終わりは、二乗余弦の曲線で 20ms かけて増減します（速いときは 1 単位の 1/4）。直線で増減すると折れ目から聞こえる「プチッ」が漏れるためです
- iPhone のマナーモードでも鳴るようにしてありますが、鳴らない場合は消音スイッチを確認してください

### 受信のしくみ

マイクの音を AudioWorklet（音声処理スレッド）で 1 サンプルも飛ばさずに見ています。約 11ms ごとの窓で目当ての周波数の強さを測り、
0.5〜1.9kHz 下の 8 点の中央値と比べた差（dB）で「鳴っている / いない」を判定します。差で見るので周りの雑音が変わっても合わせ直す必要がありません。
長さは音声の時計で測るので、画面の処理が詰まっても ・ / ー の判定がぶれません。

## 欧文 / 和文

**和文**に切り替えると和文モールス（カナ）になり、回路図もカナの木に切り替わります。欧文の図と同じく S が真ん中で、・ で始まる符号は右へ、ー で始まる符号は左へ進み、枝分かれは ・ が上・ー が下です。

- 濁点・半濁点は「清音 + ゛」の 2 文字で送り、受信側で 1 文字にまとめます（カ ゛ → ガ）
- SEND にはひらがなもそのまま入れられます（カタカナに直して送ります）。小さい文字は大きい文字として送ります（ッ → ツ）。漢字は送れません
- 長音「ー」、読点「、」、句点「。」、数字（欧文と同じ符号）にも対応しています

### 対応文字（欧文）

アルファベット A〜Z の 26 文字に加え、数字 0〜9 と「. , ?」に対応しています（回路図に出るのは A〜Z）。

## 動作確認

Playwright の端末プリセット（画面サイズ・タッチ操作）で、縦向き・横向きともに以下を確認しています。
ページやチャートがスクロールしないこと、ボタンが画面内に収まり見た目の位置でタップに反応すること、
モールス入力が正しくデコードされることをチェックしています。

- iPhone: SE(1st) / 13 / 14 Pro / 15 / 16 / 16 Plus / 16 Pro / 16 Pro Max / 16e
- Android: Pixel 7 / 9 / 9 Pro XL、Galaxy S9+ / S24 / A55 / Z Flip 6 / Z Fold 6（カバー画面・メイン画面）

横向きではチャートを左側いっぱいに表示し、表示パネルと操作パネルを右側の列にまとめるレイアウトに切り替わります。
